# Mapping agent — progress

## 2026-10-31 — wave 1 (branch `agent/mapping`)

### What is built
Package `mapping` (`mapping/__init__.py`) with the frozen API from `contracts/mapping.md`:
- `read_table(data, filename) -> Table` (`reader.py`). CSV: encoding detection (UTF-8 with or without BOM, UTF-16 BOM, CP1252, latin-1 as a last resort), delimiter sniffing (`;` `,` tab `|`), skips leading title rows, skips empty and trailing rows, handles quoted multi-line cells, gives 1-based source line numbers, names duplicate and empty headers (`Betrag (2)`, `Spalte 4`). XLSX through openpyxl: first sheet, read-only, cached values instead of formulas, dates as `dd.mm.yyyy`, numbers without float noise, percent-formatted cells as `19%`. `.xls` and broken files raise `TableReadError` with a German `message_de`. No pandas.
- `propose(table, seller_profile, provider="heuristic", *, send_real_values=False, client=None) -> Mapping`.
  - `heuristic.py` (offline): German and English synonym dictionary for about 30 concepts, with negative words and a buyer-prefix rule (`KdName`, `KdPLZ`). Value-pattern profiles check for dates (dmy/iso), German, English or ambiguous decimals, e-mails, IBANs (never mapped), VAT ids, postcodes, countries, units and plausible VAT rates. It picks transforms from the closed list (`abs` only when a column has negative values; `gross_to_net` when only gross prices exist). It detects the grouping mode from repeated numbers or continuation rows. If no column exists it adds constants from `seller_profile.defaults` (vat_rate, vat_category, unit), `DE` and `EM`. It never maps seller fields. `/buyer_reference` stays unmapped when there is no column. Each field gets a confidence and a German `reason_de`, and reasons contain no cell values.
  - `ai.py` (`provider="anthropic"`): reads `ANTHROPIC_API_KEY`, `AI_MODEL` (default `claude-sonnet-5-5`) and `AI_MAX_SAMPLE_ROWS` (default 5). By default it sends only headers and value shapes; real values go out only with `send_real_values=True`. It asks for strict JSON and validates the reply (targets, transforms, columns, one of source/constant, no seller fields). Missing constants are filled from the heuristic. On any error, timeout, invalid reply or missing key it falls back to the heuristic with `provider="heuristic-fallback"`. Only the exception class name is logged, never the prompt.
- `apply(table, mapping, seller_profile) -> (invoices, row_errors)` (`apply.py`). It groups rows (`row_per_line` with continuation rows, `row_per_invoice` with a duplicate check), applies the transforms, and runs `gross_to_net` with the line's own rate. Credit notes become 381 with positive amounts; mixed signs in one invoice give `negative_amount`. The seller block comes from the profile. Payment values come from `payment_defaults`, with due_date = issue_date + payment_days and an IBAN mod-97 check. Exemptions come from `defaults.vat_exemptions`. It restores the leading zero of DE postcodes that Excel dropped and maps country names to ISO codes. Every invoice is checked against `invoice.schema.json` with FormatChecker. RowError codes follow the contract (including `invalid_value`, `bad_iban` and `missing_exemption` from b7750f2). German messages look like `Zeile 3: Rechnungsdatum '31.13.2026' ist kein gültiges Datum`. **An invoice with any RowError is not returned; only its errors are.**
- `targets.py` is the single list of allowed targets and transforms; a test checks every target against the schema. `scoring.py` scores a mapping against the ground truth.

### Stubs / not done
- The real Anthropic call has not been made (no key locally). `test_real_anthropic_call` is marked `network` and is skipped unless `ANTHROPIC_API_KEY` is set.
- `/type_code` is decided by amount signs only. A "Belegart = Gutschrift" column with positive amounts is not used.

### Open issues
- No target exists for a line net amount or a line gross amount. Such columns are used only when there is no quantity column (quantity is then the constant 1) or as `source/expected_totals` in `row_per_invoice` mode.
- Combined columns (`PLZ Ort`, `Straße Nr PLZ Ort`) cannot be split with the closed transform list.
- Percent values stored as fractions in Excel without percent formatting (0.19) are not scaled.
- In `row_per_invoice` mode a duplicate invoice number rejects both rows.

## 2026-11-01 — AI provider made hybrid (after CI run 41255736670: raw AI scored 27 % on lexware_like)
- **Diagnosis.** The call worked; only the raw AI mapping scored low. CI does not keep the raw answer, so the cause is not proven. The most likely cause is that the scorer compared transform lists exactly, and the model probably added `strip` to fields, which is a no-op because `apply` trims every cell. The 27 % (about 4 of 15) fits fields such as the mode, the EM constant, dates and the category being the only matches. Value shapes also hide units and country names. Fixes:
  - the scorer ignores `strip`, and AI fields have `strip` removed;
  - the prompt now has per-transform rules ("do NOT use strip", one decimal transform, the rate column for both vat_rate and vat_category, etc.);
  - the request now sends value-free `column_hints` (the heuristic's type detection, e.g. "Werte sind Mengeneinheiten");
  - invalid AI fields are rejected one at a time instead of the whole answer.
- **Hybrid** (`mapping/ai.py`): the heuristic runs first. The AI may only add unmapped targets or replace heuristic fields with confidence < 0.6. It may not reuse a column the heuristic mapped with confidence >= 0.6, except the vat-category, scheme and expected-totals targets. A quality guard runs `apply` on the first 200 rows; if the hybrid gives fewer valid invoices or more RowErrors than the heuristic, the AI fields are dropped. `provider="anthropic"`, `model`, and `field_sources` = {target: "heuristic"|"ai"} (top-level, see request 8).
- **Debug.** With `MAPPING_AI_DEBUG=1` the mapping carries `debug_ai` (the raw AI field list and the rejected fields with reasons; no cell values, no reasons). The network test turns it on and prints `[mapping-ai] ...` lines through `capsys.disabled()`, so they also show when the test passes. It makes exactly one API call; the raw-AI-only score comes from the same response.
- The network test now asserts hybrid required score >= heuristic score and >= 0.8. A dry run with a fake client (sloppy answer: strip everywhere, Netto as the unit price, one bogus target) gave: raw AI 93 %, hybrid 100 %, 1 call.
- Tests: `mapping/tests` 119 passed, 1 skipped; integration 8 passed; `make test` 240 passed.

## 2026-11-01 — wave 4 fix round (review H1, M3, M4, M5, M6, L6)
- **H1 reader limits** (`mapping/reader.py`, module constants): input ≤ 10 MB; XLSX checked as a zip *before*
  openpyxl (sum of declared `file_size` ≤ 50 MB, ≤ 1000 members, ratio ≤ 100 for members > 1 MiB; zipfile never
